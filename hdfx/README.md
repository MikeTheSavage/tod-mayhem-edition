# HD Effects (TOD HD's d3d9.dll in Gameplay+)

The graphics effects of the TOD HD remaster that need **no new art**, in the player's normal GOG game. The TOD HD
`d3d9.dll` proxy is used **exactly as released** (no fork); Gameplay+ ships its own `tod_hd_fx.ini` (every effect that
needs TOD HD art switched off, the window / resolution keys off) and builds the game-derived data on the player's own
machine from their own `blocks.naz`.

Status: built, part of the installer (group "HD Effects", off by default), checked in game on a test copy (see
"Testing").

## What ships

| Path in the game folder | Where it comes from |
|---|---|
| `d3d9.dll` | `hdfx\release\d3d9.dll` = the TOD HD release DLL, 8,501,760 B, sha256 `c34aab177364ad211e91796c33efce8655146777460a43fcc5d2267c74ee5f8f` (`hdfx_stage.RELEASE_SHA256`; TOD HD build 2026-10-01, commit 480cddd, 3182 gates). Checked before every install. |
| `tod_hd_fx.ini` | `hdfx\payload\tod_hd_fx.ini`, generated by `hdfx\tools\make_ini.py` from the TOD HD release ini, then the installer's sub-toggle keys; a player's own edited values survive a reinstall |
| `tod_hd_light.txt` | TOD HD's material-class rows (roughness, metal, F0, specular, wrap, reflect): TOD HD's own data |
| `tod_hd_fx\light\classes.txt`, `emitters.txt` | TOD HD's texture-name -> material-class list and emitter list (names only, no game bytes) |
| `tod_hd_fx\particles\keys.txt`, `kinds.txt` | which texture leaves are sprites / smoke / heat (names only); `keys.txt` = the key + class columns of TOD HD's sprite manifest |
| `tod_hd_fx\sky\keys.txt` | the skybox face texture keys (names only) |
| `tod_hd_fx\volumetric\cones.txt`, `terrain\triplanar.txt` | lamp-cone mesh shapes and per-texture world scales measured by TOD HD's tools from the shipped meshes (numbers, no game bytes) |
| `tod_hd_fx\water\water.txt`, `water_normal.dds`, `water_foam.dds`, `SOURCES.txt` | which textures are water (names) and two textures **generated procedurally** by TOD HD's `tools\make_water_tex.py` (no download, no game data) |
| `tod_hd_fx\light\manifest.txt` | **generated on the player's PC** (`hdfx_regen.py`): the bytes of every classified texture in *their* archives |
| `tod_hd_fx\particles\manifest.txt` | **generated**: the sprite textures' bytes |
| `tod_hd_fx\sky\manifest.txt` | **generated**: the jungle skybox faces' bytes (only for `sky_scope`) |
| `tod_hd_fx\light\sh.txt` | **generated**: the sky irradiance (9 SH coefficients) baked from the game's own jungle skybox |

Generated files hold hashes and the first 32 bytes of game textures, so they are never shipped. TOD HD's own copies
are useless here anyway: they describe its HD texture pack (16 of the 3,507 material rows match a vanilla texture).

Licences: no third-party data is shipped. Everything in `hdfx\payload` is the TOD HD project's own data (same author);
the water textures are procedural. The Poly Haven HDRIs, the JangaFX sheets and every other downloaded asset stay out.

## (A) / (B): which TOD HD features come over

(A) = no new art: procedural, shader-only, or driven by data the installer recomputes from the player's own files.
(B) = needs new or replacement art (textures, models, HDRIs, sheets, scans) or the lighting rebake.

| Feature (ini keys) | | Why |
|---|---|---|
| Anisotropic filtering (`aniso_all`) | A | sampler state only |
| Frame cap (`fps_cap`) | A | timing only |
| Post pass: grade, tone curve, sharpen, FXAA, dither (`post` + 17 keys) | A | one pixel shader on the game's own scene copy |
| Readable depth (`depth`) | A | the game's depth surface handed back as an INTZ texture |
| Ambient occlusion: HBAO (`ssao`, `ao_mode = 1`) | A | depth only; GTAO (`ao_mode = 2`) and the 12-tap sampler (`0`) are there too |
| Sun shafts, height mist (`light_shafts`, `mist`) | A | depth + the level's own light 0 |
| Particle mipmaps, soft particles (`particle_mips`, `soft_particles`) | A | needs the sprite manifest: **regenerated** from vanilla (161 rows) |
| Lit smoke, heat haze (`part_lit`, `heat_haze`) | A | sprite manifest + kinds (names) |
| Per-pixel lighting (`lighting_mode`, `light_classes`, `specular` ...) | A | needs `sh.txt` (the DLL keeps the lighting OFF without it): TOD HD's is baked from a Poly Haven HDRI, ours is **baked from the game's own jungle skybox**; the class map is **regenerated** (3,335 rows) |
| Screen-space reflections (`ssr`, `ssr_env = 0`) | A | marches the previous frame; the HDRI fallback stays 0 |
| Triplanar slopes (`terrain_triplanar`) | A | re-projects the game's OWN texture on steep terrain (scales in `triplanar.txt`) |
| Water (`water_mode`) | A | its two textures are procedural (no art); water identities come from the class map |
| Volumetric beams + their light (`volumetric_beams`, `volumetric_light`) | A | replaces the game's painted beam sprites / cones by a march; needs only the sprite manifest + `cones.txt` |
| Emissive lights (`emissive_lights`) | A, inert | data is A, but the DLL only uses it at `lighting_mode = 2` (in mode 1 the bake already holds the lamps' light); shipped 0 |
| Dynamic sun shadows (`dyn_shadows`, `dyn_shadow_*`, `dyn_shadow_select`) | A | characters, weapons and vehicles drawn into a shadow map from the level's own sun; casters are found through the (regenerated) class map |
| Static sun shadows (`static_shadows`) | A, off | the static world into cached cascades, computed live; heavier, TOD HD ships it off too |
| Tone curve AgX / ACES (`tonemap_curve`) | A, off | shader only; off as in TOD HD |
| Ground parallax (`parallax`) | B | height maps: Poly Haven scans and hand-made maps |
| Shine (`shine`) | B | samples the HDRI reflection maps (`tod_hd_fx\env`, Poly Haven HDRI). A vanilla-skybox reflection bake is possible (it would be A) but is not built |
| HDRI reflections (`env`) | B | replaces the game's own reflection maps with HDRI ones |
| Local reflections (`local_reflections`), clear coat (`clearcoat`) | B | rebuild / read those HDRI maps; nothing to work on without them |
| Sky dome, sun disc, sky sets (`sky_dome`, `sun_disc`, `sky_sets`) | B | the HDRI panoramas |
| Ambient rebalance (`ambient_warm`) | B | per-sky-set SH from the HDRIs |
| Level looks (`level_looks`) | B | recognises a level through the forest's placement files |
| The forest (`veg*`) | B | models and atlases |
| Texture / model replacement (`tex_override`, `tex_pbr`, `replacement_models`, `vehicle_hd`) | B | new art |
| Terrain rock (`terrain_rock`) | B | rock scans |
| Flipbook sprites (`part_flipbook`, `part_flipbook_once`) | B | JangaFX sheets |
| Explosion flash / embers / ring (`explosion_fx`) | B | a burst is detected only through the flipbook's one-shot rows, and the ring is a JangaFX sheet |
| Yard decals (`yard_decals`) | B | painted decal images |
| Rebake sun shadows (`sun_shadows`) | B | see below |

**`sun_shadows`** is not regenerable on a player's PC. Its two maps ARE computed from the game's geometry,
but by an offline Cycles bake of MM010 (Blender, hours), and the DLL applies the
term only to the 49 jungle receiver meshes whose vertex-colour buffers hash (SHA-1) to the **rebaked** colours. With
the shipped colours nothing matches and the feature is a no-op by its own contract; making it match means rewriting
MM010's baked lighting with the rebake, which TOD HD itself keeps frozen. `static_shadows` (A) is the live replacement
and covers every level.

## No fork

Every possible reason to fork has an answer without changing the DLL:

- **Logs**: `LogDir()` reads `TODHD_LOG_DIR` at its first log line and refuses a folder at or under the DLL's own
  folder; the compiled fallback is a fixed folder on the TOD HD development machine (it creates only the leaf, so on
  other PCs it fails quietly). The Gameplay+ `dsound.dll` loader (`dll\loader\dsound_proxy.cpp`
  `set_hdfx_log_dir`) sets `TODHD_LOG_DIR = %LOCALAPPDATA%\TODGameplay\hdfx_logs` (or `[loader] hdfx_log_dir`) in its
  DllMain, creating the whole path, unless the variable is already set. Order: the d3d9.dll's DllMain never logs (it only
  swaps USER32 IAT slots); its first line is written at TOD.exe's first USER32 call in WinMain or at Direct3DCreate9,
  both after every static import's DllMain.
- **Display**: `borderless = 0` (no subclass, no window filter), `dpi_aware = 0` (logs only), `resolution_lock = 0`
  (never patches the SetResolution thunk 0x420130) in our ini.
- **Exe**: the DLL checks no exe hash and does not need the LAA exe (TOD HD itself runs on an LAA-patched copy, md5
  988808a8...; Gameplay+ requires the plain GOG exe, md5 d9beb351...). Its only exe check is the resolution lock's
  (TimeDateStamp 0x4308B92F, SizeOfImage, 11 code signatures), identical on both exes, and unused here.
- **Missing data is safe**: every feature checks its file at start and logs a no-op instead (no `sh.txt` -> the lighting
  stays off; no sprite manifest -> particles do nothing; no shadow package / env maps / sheets / height maps -> those
  features stay off).

### Re-syncing with a newer TOD HD release

1. Verify the new TOD HD release folder against its `RELEASE.txt` (hash lines `<sha256>  <path>  <size>`).
2. Copy `d3d9.dll` and `tod_hd_fx.ini` into `hdfx\release\`; copy
   `tod_hd_light.txt`, `tod_hd_fx\light\classes.txt`, `emitters.txt`, `particles\kinds.txt`, `sky\keys.txt`,
   `volumetric\cones.txt`, `terrain\triplanar.txt` and `water\*` into `hdfx\payload\`; rebuild
   `particles\keys.txt` from the new sprite manifest's key + class columns.
3. Update `RELEASE_SHA256` in `hdfx\tools\hdfx_stage.py`.
4. `python -I hdfx\tools\make_ini.py`; review new keys: a new feature that needs art goes into `B_OFF`, a new (A)
   default into `GP_VALUES`.
5. `python -I installer\tests\test_installer.py` (checks the shipped ini still has every key the installer sets, that
   every (B) key is 0 and that the DLL is the pinned release), then one in-game run on a test copy.
Never write anything into the TOD HD folder itself.

## Installer group "HD Effects"

`installer\gpi\catalog.py` (group `hdfx`), `plan.py` (`HDFX_SUBS`, `HDFX_FILES`), `engine.py` (step `hdfx`).

| Sub-toggle | tod_hd_fx.ini keys (on / off) |
|---|---|
| Texture filtering | `aniso_all = 16 / 1` |
| Ambient occlusion | `ssao = 1 / 0` |
| Post: sharpen, FXAA, grade | `post = 1 / 0` |
| Light shafts, mist, volumetric beams | `light_shafts`, `mist`, `volumetric_beams`, `volumetric_light` = 1 / 0 |
| Particles | `particle_mips`, `soft_particles`, `part_lit`, `heat_haze` = 1 / 0 |
| Lighting | `lighting_mode = 1 / 0` |
| Water (needs Lighting) | `water_mode = 1 / 0` |
| Real-time shadows (needs Lighting) | `dyn_shadows = 1 / 0` |
| Static world shadows (needs Real-time shadows; default off) | `static_shadows = 1 / 0` |
| Frame cap 60 | `fps_cap = 60 / 0`; on also writes `[timing] fps_limit = 0` (one limiter) |

On: stage everything (the release DLL after its sha256 check, the ini merged with the player's own tuned values, the
payload, the manifests and `sh.txt` built from the game's archives as configpc.txt lists them, after the data zip
step), then copy. Another program's `d3d9.dll` is set aside as `d3d9.dll.before_hdfx` (warning, also in the backup);
a TOD HD install (a TOD HD d3d9.dll with its own non-Gameplay+ ini) is refused. Off: exactly `HDFX_FILES` are removed
(only when the ini is ours), empty `tod_hd_fx` folders go, and a set-aside d3d9.dll comes back. The group needs the
dsound loader (the log folder), so it counts as a DLL group.

## Gameplay+ defaults that differ from TOD HD

- The grade: TOD HD's (exposure 0.18, contrast 1.10, saturation 1.08, warmth 0.12, vignette 0.08, lift -0.010) was
  tuned on its HD textures and HDRI sky; on the vanilla textures, whose sunsets are already pink-orange, it pushes the
  picture further orange. Gameplay+: exposure 0.08, contrast 1.06, saturation 1.04, warmth 0, vignette 0.05,
  lift -0.005 (compared in one session: effects off, TOD HD grade, Gameplay+ grade).
- On (TOD HD ships them off, its player runs them on): `part_lit`, `heat_haze`, `volumetric_beams`, `volumetric_light`,
  `terrain_triplanar`, `water_mode`, `dyn_shadows`, `dyn_shadow_select`.
- `lighting_mode = 1` (ADD: the game's bake kept, the level's sun added per pixel, gated by the bake's shadow), not the
  TOD HD player's mode 2: mode 2 replaces the bake with the sun + an SH sky, and with only the game's own skyboxes (no
  per-level HDRI sky sets) every non-jungle level would get sun without fill (TOD HD's own known mode-2 bug outside
  MM010). `sky_scope = 1`: the baked sky ambient only on levels drawing the jungle's skybox, as in TOD HD.
- `mist_height = -130` is MM010's floor (a world y), as in TOD HD; in the city the mist is effectively off.

## Testing

Checked with an in-game test harness on a copy of the game (not included): scripted input, USERPROFILE and
LOCALAPPDATA isolated, everything put back and compared afterwards. Every run left the test copy, the real saves and
the GOG files byte-identical, wrote nothing into the TOD HD folder, and restored the registry at 1920x1080. Windowed
1920x1080.

What was compared:

* MM010 jungle intro at the same cutscene time, and the zipline: vanilla / Gameplay+ / Gameplay+ with HD effects.
* Downtown City Hall plaza (save d12), same spot, standing and after walking.
* Each effect on its own in one session: off / AO only / all but lighting / all but post / all with the TOD HD grade /
  all with the Gameplay+ grade.
* AO on vanilla geometry (`ao_debug = 1`) and dynamic shadows (`dyn_shadow_debug = 1`: player, pedestrians, cars red);
  the player's shadow at the feet (off / AO only / all).
* Front-end resolution change 1920x1080 -> 2560x1440 (device Reset) with the effects on. Log: depth texture released
  before Reset, `Reset hr=0`, INTZ / AO / volumetric / SSR / soft-particle / shadow targets made again at the new size.
* Physics + difficulty + MAYHEM title + HD effects with a Box3D explosion, and the title with the MAYHEM overlay.

In the plaza the lighting relit ~78 % of the world draws (99 % with their own material row), the shadow map took ~3,000
caster draws a second (characters, cars, guns) and SSR marched ~6,000 draws a second; sky ambient OFF there (city
sky), ARMED in the jungle. In the jungle intro cutscene and in the front end the level's light 0 points up, so the
lighting and the shadows stand aside there (AO, post, shafts, mist and the particle work still run).

**Cost** (Downtown plaza, 1920x1080, uncapped, effects-on vs effects-off windows of 5 s alternated live in one
session, paired medians): all effects +1.1 ms (session 1, 6 pairs) and +1.8 ms (session 2, 7 pairs) on an 18.3-19.6 ms
effects-off frame. The game in this setup is not GPU-bound (about 50-55 fps with everything off, background window), so
single features drown in the ±2 ms window noise: dynamic shadows measured -1.5 / +1.1 ms, static shadows -0.1 / -0.5 ms
(unresolvable here). TOD HD's own paired GPU measurements at 3024x1964 apply: dynamic shadows +0.36 ms for a frame of
51 casters, static shadows 0.2-1 ms, HBAO +0.04-0.10 ms over AO off (from TOD HD's own notes).

**Memory** (32-bit process, GOG exe, not LAA; peak over the run): jungle intro private bytes 270 (vanilla) / 282
(Gameplay+) / 314 MB (+ HD), address space in use 613 / 652 / 661 MB; Downtown 326 / 329 / 391 MB private, 685 / 660 /
759 MB address space, largest free block 950 MB with the HD effects (1,118 MB without). Physics + difficulty + HD:
398 MB private, 762 MB address space. The DLL's D3DPOOL_DEFAULT targets (32 MB shadow map, 8 MB depth texture, ~20 MB
of half-res targets at 1080p) live in video memory.

**Logs**: `%LOCALAPPDATA%\TODGameplay\hdfx_logs\todhd_fx.log` + `todhd_load.txt` (proved with LOCALAPPDATA pointed at
the isolated profile: the loader created the path, nothing appeared in the game folder or in the TOD HD folder).

## Known limits (not verified yet)

- An IN-GAME resolution / mode switch (Reset) with the effects on: only the front-end SETTINGS switch ran (the key
  script could not open the pause menu). The in-game mode switch of `[display]` ([../display/README.md](../display/README.md)) uses the same
  Reset path.
- Exclusive fullscreen and borderless with the effects on (only windowed 1920x1080 and a 2560x1440 window ran).
- Frame cost per feature in game (see Cost); the native 3024x1964 size in game (TOD HD's own numbers are at that size).
- MAYHEM title: 1 of 12 captures with the HD effects had no MAYHEM overlay (0 of 12 without), and one capture 8 s into
  the title was black; not reproduced further (the MAYHEM title has had a newer version since).
- A long play session; levels other than MM010 and Downtown; the water shader was enabled but no water was on screen
  in the runs.
- `ssr` and `terrain_triplanar` look on vanilla textures was not judged separately.
- The installer's HD Effects step on a real game folder (unit tests on fake folders only; the staging itself ran
  against the GOG folder read-only, 12-15 s, up to 2 min on a busy disk).

## Install

Close TOD, start the visual installer (`Gameplay Plus Installer.cmd`), tick "HD Effects", install. It backs the
folder up, builds the data from the game's own archives, sets the GOG folder's existing `d3d9.dll` (the inert capture
proxy) aside as `d3d9.dll.before_hdfx`, and copies the files above. Off: untick and install, or Restore a backup.
